# verify_08 (8장 브리지 네트워크와 포트 게시)
확인한 절: 코어 1~4 전 절, 실무 적용 시나리오 4개, 인출 질문 8개. 원천: docker 12.1~12.6, 15.4, 15.5, 16.2 대조.
수정 2건
- 🎮 박스: "컨테이너 안에서 80번을 listen해도 호스트에서는 아무도 그 포트를 열지 않은 상태" → docker 12.4(docker-proxy가 호스트 게시 포트를 직접 bind)와 충돌하는 단정. "컨테이너 자기 네임스페이스 안의 소켓일 뿐 ... 보완용 docker-proxy가 호스트 포트를 bind하는 경우는 코어 3"으로 정정.
- 기억 고리 C++ 유추의 "호스트 8080은 열지 않는다" → "호스트 8080으로 오는 패킷은 기본적으로 커널 DNAT가 넘긴다(docker-proxy는 보완용)"으로 정정. 같은 이유.
삭제 0. 나머지(MASQUERADE·FDB·DNAT 경로 도식·userland-proxy 기본값·Engine 28 동작·Desktop 제외·라우팅 메시 표)는 원천과 일치. 기존 [보충] 3개(ping 예시, nsenter, 127.0.0.1 게시 조언)는 정당.
남은 불확실성: docker-proxy가 현재 환경에서 실제로 얼마나 관여하는지는 원천 두 장(12.4/15.4)이 서로 다르게 서술 — 본문 [보충]이 이미 기록하고 ps 명령으로 확인하게 함.
