# 이 문서로 공부하는 법
{: .no_toc }

이 사이트의 세 권(C# 방치형 RPG 서버, NestJS SaaS 백엔드, Docker·Kubernetes)은 뇌과학·인지심리학 기반 학습법(코어 암기, 정교화, 인출 연습, 간격 반복, 거꾸로 독서, PACER)에 맞춰 **본문을 코어 중심으로 다시 쓰고 장 순서를 바꾼** 판입니다.

- **누구를 위해:** C++로 TCP/소켓 실시간 게임 서버를 만들어 온 개발자가, C#·HTTP 웹 백엔드·NestJS·Docker/Kubernetes로 **실무 구현을 시작하기 전에** 알아야 할 이론을 익히는 용도입니다.
- **어떻게 바꿨나:** 장마다 코어(최대공약수)를 맨 앞에 두고 본문 절을 코어 단위로 다시 묶었습니다. 이미 아는 C++·소켓 서버 지식에 새 개념을 거는 유추 표, 실무 시나리오 문제, 인출 연습을 붙였습니다. 원문의 사실·코드·출처 표기는 모두 유지했습니다.

## 1. 왜 이렇게 바꿨나 — 세 가지 사실

| 사실 | 의미 | 이 사이트에서의 처방 |
|---|---|---|
| **유창성 착각** — 다시 읽고 밑줄 그으면 눈에 익을 뿐, 꺼낼 수는 없다 | "술술 읽힌다" ≠ "안다" | 장 끝의 **🧠 인출 연습**을 본문을 덮고 먼저 푼다 |
| **인출이 기억을 만든다** — 4번 읽은 집단보다 1번 읽고 백지에 꺼낸 집단이 1주 뒤 훨씬 많이 기억했다(Roediger & Karpicke, 2006) | 꺼내려고 애쓰는 "답답함"이 장기기억 스위치(바람직한 어려움) | 백지 복습, 인출 질문, 답은 접어 둠 |
| **소화 없는 입력은 버려진다** — 소비(읽기)만 하고 소화(정리·연결·실습)를 생략하면 대부분 잊힌다 | 읽은 양 ≠ 남은 양 | 장을 읽으면 그 장의 인출 연습을 끝내기 전에는 **다음 장으로 넘어가지 않는다** |

## 2. 한 장의 구조와 공부 순서

모든 장은 같은 순서로 되어 있습니다. 위에서 아래로 따라가면 그대로 학습 루틴이 됩니다.

```
[머리말]   🎮 게임 서버 개발자에게 / 🎯 실무에서 이 장이 필요한 순간
   ↓
[코어]     이것만은 100% — 한 문장 + 코어 3~5개 (먼저 읽고 외운다)
   ↓
[연결]     C++·TCP 서버 경험에서 출발하기 — 유추 표 (같은 점 / ⚠️ 다른 점)
   ↓
[준비]     🧭 읽기 전에 — 사전 질문에 추측으로 답하기 + 처리법(실습/관계도/카드)
   ↓
[본문]     코어 1 → 코어 2 → … (절마다 "한 줄 요약" → 세부). 여백 누적 요약(3절)
   ↓
[적용]     실무 적용 — 체크리스트 + 시나리오 문제(답은 접혀 있음)
   ↓
[인출]     🧠 인출 연습 — 책 덮고: 백지 복습 → 인출 질문 → 기억 고리 → 거울 설명
   ↓
[복습]     10분 → 1일 → 1주 → 1달 (각 5분 인출) + 플래시카드
```

### 각 부분의 역할

| 부분 | 근거 학습법 | 하는 일 |
|---|---|---|
| 🎮 **게임 서버 개발자에게** | 정교화 부호화 | 새 주제를 이미 아는 경험의 어디에 걸지 먼저 정한다 |
| 🎯 **필요한 순간** | 상황의 힘·학습 동기 | "언제 이걸 모르면 사고가 나는가"를 알고 읽으면 밀도가 달라진다 |
| **코어** | 피라미드식 N차 요약·코어 암기·결정적 지식 | 장의 최대공약수. 이것만은 100% 외우고, 본문 세부는 코어에서 파생된 것으로 읽는다 |
| **C++·TCP 유추 표** | 정교화·PACER의 A(유추) | 같은 점으로 빨리 이해하고, **⚠️ 다른 점**에서 C++ 습관이 만드는 버그를 미리 막는다 |
| 🧭 **사전 질문** | 생산적 실패·거꾸로 독서 | 모르는 지점을 먼저 자각하면 배울 준비가 된다. 추측으로라도 답을 적어 둔다 |
| **코어별 본문** | 조직화(청킹) | 흩어진 절을 코어 단위 묶음으로 재배치. 각 절은 한 줄 요약부터 |
| **실무 적용·시나리오** | 인출 연습·전이 | "이런 장애가 났다, 왜?"로 지식을 실제 상황에서 꺼내 본다 |
| 🧠 **백지 복습·인출 질문** | 활성 회상·바람직한 어려움 | 답은 접혀 있다. 먼저 말하거나 쓰고 나서 연다 |
| 🧠 **기억 고리·가르치기** | 3의 법칙·거울 학습법·랜덤 논리 게임 | 원고 없이 설명하다 막히는 곳이 지식의 구멍. 트레이드오프는 양쪽을 번갈아 변호 |
| 🧠 **간격 반복** | 에빙하우스 망각곡선 | 잊힐 무렵 5분씩 꺼내기 |

### 장 순서를 바꾼 이유

| 책 | 바뀐 순서 | 이유 |
|---|---|---|
| Docker·Kubernetes | **"인프라 전체 그림"을 맨 앞(1장)으로** → 리눅스 → Docker → 쿠버네티스 → 운영 | 인프라 경험이 없으면 세부보다 지도가 먼저다(거꾸로 독서) |
| C# 서버 | 문법 → 객체지향 → **메모리·GC(3부로 당김)** → … → 웹 API → ASP.NET Core → **설계 원칙(9부로 미룸)** → EF Core → … | C++과 가장 크게 다른 메모리 모델을 일찍 잡고, 설계 원칙은 DI·미들웨어를 직접 본 뒤 원리로 되짚는다 |
| NestJS SaaS | TypeScript → Node.js → **NestJS(3)** → API 설계 → 보안 → 데이터 → 운영 → 테스트 → **아키텍처·DDD·멀티테넌트(마지막)** | 실제 구현 순서(요청 하나 만들기 → 지키기 → 저장 → 안 죽게 → 검증 → 구조 설계)를 따른다 |

### PACER — 정보 종류별 처리법

| 기호 | 정보 종류 | 이 책들에서의 예 | 처리 |
|---|---|---|---|
| 🛠 P | 절차 | `docker run`, `kubectl apply`, 코드 예제, 미들웨어 등록 | **즉시 실습.** 따라 칠 수 없는 상황이면 읽기를 멈춘다 |
| 🔗 A | 유추 | 이벤트 루프 ≈ epoll 리액터, JWT ≈ 서명된 세션 티켓, Pod ≈ 서버 프로세스 묶음 | 이미 아는 것과 비교하고 **유추가 깨지는 조건**을 찾는다 |
| 🗺 C | 개념 | 컨트롤 플레인 구성요소 관계, DI 컨테이너와 모듈 관계 | 선형 노트 대신 **관계도(마인드맵)** 로 그린다 |
| 📦 E·R | 증거·참조 | 종료 코드 137, 포트 번호, HTTP 상태 코드, 옵션 이름 | 지금 외우지 말고 **플래시카드**로 보내 간격 반복 |

## 3. 정독할 때 — 여백 누적 요약 (Jeffrey Kaplan)

긴 절을 읽을 때는 노트나 여백에 다음 규칙으로 적습니다. 베껴 쓰지 말고 반드시 압축합니다.

```
1문단 → [1문단 요약 1문장]
2문단 → [2문단 요약 1문장]
3문단 → ① [1~2문단 누적 요약 1문장]  ② [3문단 요약 1문장]
4문단 → ① [1~3문단 누적 요약 1문장]  ② [4문단 요약 1문장]
...
```

마지막 누적 요약 1문장을 각 장 🧠 코어의 "한 문장"과 비교해 보세요. 다르면 어느 쪽이 빠뜨렸는지 따져 보는 것 자체가 좋은 인출입니다.

## 4. 책 단위로 — 코어 노트와 플래시카드

각 책의 **📚 학습 가이드** 아래에 세 페이지가 있습니다.

| 페이지 | 내용 | 언제 |
|---|---|---|
| **코어 노트** | 책 전체의 결정적 지식 3개 + 장별 한 문장 + 지식 지도 | 책을 시작할 때 한 번(거꾸로 독서), 매주 복습 때 |
| **플래시카드** | 장별 문답 카드 (Anki 가져오기용 탭 구분 형식 포함) | 매일 10~15분 |
| **복습 계획표** | 장별 10분/1일/1주/1달 체크표 | 매일 시작할 때 |

**결정적 지식**은 수십 개의 하위 지식을 끌어당기는 원리입니다(과목당 3개 이하). 예를 들어 Docker·Kubernetes 책에서 "컨테이너는 격리된 리눅스 프로세스일 뿐"이라는 한 문장을 확실히 하면 PID 1 문제, OOM Kill, 네임스페이스, cgroups가 모두 거기서 따라 나옵니다.

## 5. 하루 운영 규칙

- **집중은 하루 약 2시간이 한계** — 고집중이 필요한 정독·인출은 그 안에 몰고, 나머지 시간은 플래시카드·복습 체크처럼 가벼운 일로 채운다.
- **웜업 5분** — 시작이 안 되면 본문 아무 절이나 5분간 베껴 쓰며 시동을 건다(웜업일 뿐, 공부 방법이 아니다).
- **"지금 뭐가 중요한데?"** — 세부에 빠질 때마다 그 장의 코어로 돌아온다.
- **제한 시간** — "이 절은 20분 안에" 처럼 상황의 압박을 일부러 만든다.

### AI를 쓸 때

| ❌ 하지 말 것 | ✅ 이렇게 |
|---|---|
| "처음부터 설명해 줘" 하고 고개만 끄덕이기 (= 원고 보고 공부하기) | "내가 ___를 설명할 테니, 틀리거나 빠진 부분만 질문으로 짚어 줘" |
| 막히자마자 정답 요청 | "정답은 말하지 말고, 내가 답에 도달하도록 단계별 질문을 던져 줘" |

## 6. 점검 체크리스트

- [ ] 본문을 펴기 전에 제목 예측과 사전 질문에 답을 적었다
- [ ] 실습(P) 항목은 읽자마자 직접 실행했다
- [ ] 장이 끝나면 책을 덮고 코어 3줄을 말할 수 있다
- [ ] 백지 복습에서 못 채운 칸만 골라 다시 읽었다
- [ ] 원고 없이 1분 거울 설명을 했고, 막힌 곳을 표시했다
- [ ] 오늘 해야 할 간격 반복(10분·1일·1주·1달)을 끝냈다
- [ ] 소화하지 못한 장이 쌓였다면 새 장 읽기를 멈췄다
