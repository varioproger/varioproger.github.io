## 1. 이 사전의 읽는 법

**N**은 Namespace 범위, **C**는 클러스터 범위다. 같은 이름이어도 N 객체는 Namespace가 다르면 구분된다. C 객체는 Namespace 밖에서 관리한다. 이름을 보고 실제 서버나 프로그램이라고 생각하지 말고 **“이 기록을 읽는 주체는 누구인가?”**를 함께 확인한다.

이 표는 일반 앱 운영에서 자주 만나는 핵심과 주요 확장을 모았다. 모든 Kubernetes API의 전수 목록은 아니다. 실제 클러스터의 `kubectl api-resources`, `kubectl explain <종류>`, `kubectl get crd`가 그 환경에 설치된 API를 확인하는 출발점이다.

**Lease:** Node heartbeat는 Node 상태 보고만으로 생각하지 않는다. `kube-node-lease` Namespace의 Lease 갱신도 노드 생존 관찰에 쓰인다. controller 복제본 중 어느 하나가 활성 리더 역할을 맡을지 조정하는 데에도 Lease가 사용될 수 있다. Lease 자체가 앱 트래픽을 전달하지 않는다. [Leases](https://kubernetes.io/docs/concepts/architecture/leases/).

**Quota와 LimitRange:** 팀 Namespace에 CPU requests 총량·PVC 수 같은 예산을 설정할 수 있다. Deployment 객체 생성은 수락됐지만 그 아래 Pod 생성이 quota로 거절될 수도 있다. LimitRange는 requests/limits의 기본값과 제약을 부여할 수 있다. 따라서 사용자가 쓰지 않은 기본값이 저장된 Pod에 생겨 배치 결과에 영향을 주는 경우를 확인한다. [ResourceQuota](https://kubernetes.io/docs/concepts/policy/resource-quotas/), [LimitRange](https://kubernetes.io/docs/concepts/policy/limit-range/).

**RuntimeClass:** 기본 runtime 외에 다른 격리 실행 방식을 선택할 때 연결하는 객체다. 이름을 선언하는 것만으로 노드에 해당 runtime이 설치되지 않는다. handler 지원·노드 배치·오버헤드가 맞아야 한다. [RuntimeClass](https://kubernetes.io/docs/concepts/containers/runtime-class/).

## 3. 통신·설정·저장소 오브젝트

| 객체 | 범위 | 역할 | 처리 주체 또는 연결 |
|---|---|---|---|
| Service | N | 안정적 진입점과 대상 선택 | EndpointSlice controller, 데이터 경로 구현 |
| EndpointSlice | N | 구체적인 endpoint와 준비 상태 | controller가 기록, kube-proxy·LB 구현 등이 활용 |
| Ingress | N | HTTP 진입 라우팅 규칙 | 선택한 Ingress controller |
| IngressClass | C | Ingress 처리 구현 연결 | 해당 controller |
| GatewayClass | C, 확장 API | Gateway 구현 선택 | 설치된 Gateway API controller |
| Gateway | N, 확장 API | listener 등의 진입점 | Gateway controller·실제 LB/프록시 |
| HTTPRoute | N, 확장 API | HTTP 라우팅 규칙 | 연결된 Gateway 구현 |
| ReferenceGrant | N, 확장 API | 지원되는 교차 Namespace 참조 허용 | Gateway API 구현 등 |
| NetworkPolicy | N | 선택된 Pod의 허용 ingress/egress | 지원하는 네트워크 집행 구현 |
| ConfigMap | N | 일반 실행 설정 | kubelet 주입·앱 읽기 등 |
| Secret | N | 민감한 데이터 표현 | API 권한·저장 암호화·주입 체계와 결합 |
| PersistentVolumeClaim | N | 저장소 요구와 사용 연결 | binding·provisioning controller |
| PersistentVolume | C | 실제 저장소의 Kubernetes 표현 | volume controller와 driver |
| StorageClass | C | 생성할 저장소 종류·정책 | provisioner와 CSI driver 등 |
| VolumeAttachment | C | volume을 node에 연결하려는 상태 | attach/detach 체계·CSI attacher |
| CSIDriver | C | CSI driver의 기능 정보 | Kubernetes 저장소 체계 |
| CSINode | C | 노드에 설치된 CSI driver 정보 | kubelet·저장소 체계 |
| VolumeSnapshot | N, 확장 CRD | snapshot 요청과 상태 | snapshot controller·CSI driver |
| VolumeSnapshotClass | C, 확장 CRD | snapshot driver·삭제 정책 | snapshot 체계 |
| VolumeSnapshotContent | C, 확장 CRD | 실제 snapshot과의 연결 | snapshot 체계 |

Gateway API·snapshot·VPA 등은 환경에 따라 먼저 CRD와 구현을 설치해야 한다. Kubernetes core API처럼 모든 클러스터에 당연히 존재한다고 가정하지 않는다. 한편 CRI·CNI·CSI는 이 표의 오브젝트가 아니라 **인터페이스 규격**이다.

| NodeClass | EKS Auto Mode의 별도 API | Auto Mode 노드 구성; EC2NodeClass와 구분 |

보안 확장 상세는 [Admission controllers](https://kubernetes.io/docs/reference/access-authn-authz/admission-controllers/), [Dynamic admission](https://kubernetes.io/docs/reference/access-authn-authz/extensible-admission-controllers/), [ValidatingAdmissionPolicy](https://kubernetes.io/docs/reference/access-authn-authz/validating-admission-policy/)로 이어진다. 최신 API가 자신의 EKS 버전에 포함되는지는 별도 확인한다.
