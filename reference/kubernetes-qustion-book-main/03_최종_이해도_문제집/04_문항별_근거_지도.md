# 04. 문항별 근거 지도

> 전체 학습 35/35 · 최종 점검
> [이전: 03. 최종 이해도 문제집 — 정답과 해설](03_정답과_해설.md) · [전체 목차](../README.md)

이 문서는 정답을 외우는 용도가 아니라 **정답과 해설이 어떤 근거에서 나왔는지 검증하는 색인**이다. 근거는 다음 순서로 사용한다.

1. 교재 본문에서 초보자용 연결 설명을 읽는다.
2. 공식 문서에서 제품·API의 실제 책임과 동작을 확인한다.
3. 더 깊은 배경은 [원문 분석과 독서 지도](../04_참고자료/01_원문_분석과_독서지도.md)의 PDF 약어와 페이지로 찾아간다.

공식 문서는 구조적 원리의 1차 근거다. 버전·한도·설치 절차처럼 바뀔 수 있는 값은 실제 작업 시 사용하는 EKS와 Kubernetes 버전의 문서를 다시 확인한다.

## 근거를 읽을 때 주의할 표현

- `Kubernetes가 관리한다`는 controller, scheduler, kubelet 중 실제 주체로 세분한다.
- `OCI가 설치되어 있다`고 표현하지 않는다. OCI는 구현체가 따르는 규격이다.
- `Service가 Pod IP를 고정한다`고 표현하지 않는다. Service는 안정된 진입점과 갱신되는 endpoint 집합을 연결한다.
- `HPA가 Node를 늘린다`고 표현하지 않는다. Node 공급기는 별도의 제어 루프다.
- `PDB가 장애를 방지한다`고 표현하지 않는다. 자발적 eviction에 대한 예산이다.
- AWS 문서의 한도·지원 버전·기본값은 고정 지식으로 외우지 않고 실제 환경에서 다시 조회한다.
