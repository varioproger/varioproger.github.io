범위가 큰 이유는 일반 EKS 외에 Auto Mode, 다양한 컴퓨팅, 온프레미스 연계, AI/ML, 보안·관측·운영까지 포함하기 때문이다. 파일 길이가 곧 필수 학습량은 아니다.

| 원문 범위 | 주요 내용 | 재구성 판단 |
|---|---|---|
| 31–106쪽 | 개요·구조·설정·시작하기 | 구조 31–39쪽 먼저 |
| 107–317쪽 | EKS Auto Mode | 일반 구성을 익힌 뒤 책임 차이 확인 |
| 318–484쪽 | 클러스터 생성·설정·수명 주기 | 환경 관리 단계의 참조 |
| 485–638쪽 | API 접근, access entries, Pod Identity·IRSA | 사람→클러스터와 Pod→AWS 권한 구분 |
| 639–1221쪽 | Managed Node Group 등 컴퓨팅·노드 선택 | 645–648쪽부터; 특수 노드 방식은 선택 |
| 1222–1303쪽 | 앱 스토리지 | PVC·CSI의 AWS 구현 |
| 1304–1495쪽 | VPC·CNI·네트워크·DNS·LB controller | 요청 경로를 이해하는 중심 구간 |
| 1496–1633쪽 | 워크로드 배포·LB·add-on | 실제 통합 조건 확인 |
| 1634–1873쪽 | EKS Capabilities | 기본 구조 이해 후 플랫폼 확장 |
| 1874–1903쪽 | 자원 구성·조회·관리 | 운영 참조 |
| 1904–2094쪽 | 보안 | 책임·접근·네트워크 보안 보강 |
| 2095–2180쪽 | 모니터링·로그·다른 AWS 서비스 연동 | 운영·장애 관측 |
| 2181–2283쪽 | Connector·Outposts·온프레미스 연계 | 현재 예시 범위 밖 |
| 2284–2568쪽 | AI/ML 워크로드 | 해당 용도일 때 선택 |
| 2569–2693쪽 | 도구·버전·장애 해결·오픈소스 확장 | 실행 시점의 확인 자료 |
| 2694–2772쪽 | 문서 이력·기여 및 후속 페이지 | 참고 정보 |

**추출한 핵심:** EKS가 Kubernetes 객체 모델을 대체하는 것이 아니라, 그 모델이 AWS 컴퓨팅·네트워크·스토리지·권한 위에서 작동하도록 제공한다. AWS가 맡는 운영 범위는 모드에 따라 달라진다.

## 4. 그대로 외우면 오해하기 쉬운 원문 표현

| 원문 위치·주제 | 읽을 때 필요한 구분 | 이번 교재의 처리 |
|---|---|---|
| TF 137쪽 등, S3 + DynamoDB 잠금 | 현재 S3 backend는 lockfile 방식을 지원하고 DynamoDB 기반 잠금은 deprecated | 책의 명령 복사보다 공유·잠금 원리를 학습 |
| TF 400쪽 등, EKS 버전 1.21과 기본 VPC | 당시 학습 예제의 고정값 | 현재 지원 버전·실행 환경은 공식 문서로 별도 확인 |
| TF 403–408쪽, 두 provider의 단일 예제 | 클러스터 생성과 클러스터 API 접근이 모두 준비되어야 함 | 기반과 앱의 수명 주기·접속 조건을 나눠 설명 |
| NET 142쪽, dockershim | deprecation 당시 문맥과 현재 런타임 구조가 다름 | 1.24 제거 이후 CRI·containerd 기준으로 설명 |
| LEC 22–23쪽, ALB | IBM 문맥의 ALB·NGINX와 AWS ALB는 같은 구현이 아님 | AWS Load Balancer Controller가 AWS ALB를 구성하는 모델로 분리 |
| LEC 23쪽, Ingress v1beta1 | 오래된 API 예시 | 현행 `networking.k8s.io/v1` 개념으로 설명; 원문 명령 복사 지양 |
| LEC 21쪽, ClusterIP 도표 | 인터넷에서 ClusterIP로 직접 연결되는 것으로 오해 가능 | 내부 Service 경로와 외부 LB 경로를 별도 표시 |
| NET 187쪽, ingress/egress 문장 | 유입·유출 설명이 반대로 적혀 있음 | ingress는 기준 경계로 들어오는 방향, egress는 나가는 방향 |
| NET 284쪽, LoadBalancer만 외부 접근 가능하다는 표현 | NodePort 등 다른 접근 방식이 있음 | 경로별 조건을 구분 |
| KUR 140쪽, `kubectl run` 설명 | 구버전의 Deployment 생성 동작과 현재 명령을 혼동 가능 | 현재 `kubectl run`은 Pod 생성; Deployment API 객체 중심으로 설명 |
| LEC 29쪽, PodSecurityPolicy | Kubernetes 1.25에서 제거됨 | 현행 Pod Security Admission 등과 구분해 역사적 내용으로 취급 |
| KUR 153쪽 등, Endpoints 중심 설명 | EndpointSlice와 selector 없는 Service 예외까지 고려 필요 | 일반 selector 기반 Service로 범위를 명시 |
| Kubernetes 책의 일반적인 LB 흐름 | NodePort·Service IP를 항상 거친다고 일반화하기 쉬움 | ALB IP target과 Instance target을 나눔 |
| EKS의 ‘managed’ 표현 | 모드에 따라 AWS 책임이 다름 | 일반 EKS + Managed Node Group을 기준으로 Auto Mode 차이 표시 |

교재는 위 표현을 단순 복사하지 않았다. 최신 기능 전체를 소개하기보다 구조 이해에 영향을 주는 차이만 반영했다. Ingress는 기존 구조를 읽는 데 중요하지만 API가 동결되어 있어 새로운 기능 확장은 Gateway API도 별도 검토하는 흐름이다. [Ingress 공식 안내](https://kubernetes.io/docs/concepts/services-networking/ingress/).

## 6. 원문을 읽는 3회차 경로

|---|---|

**1회차: 관계 이해.** 새 교재 01–04를 읽고 3개의 그림을 그린다. 원문의 설치 명령이나 모든 설정 필드를 암기하지 않는다.

**2회차: 설명 안 되는 화살표 보강.** TF 7장의 통합 예시와 KUR 5·9·10·7·8장을 중심으로 보고, 컨테이너가 궁금하면 SEC 3–6장, AWS 구현이 궁금하면 EKS의 구조·노드·CNI·LB 구간을 붙인다.

**3회차: 관측하며 실습.** 컨테이너 하나 → 로컬 Kubernetes의 Deployment·Service → 이미지 교체·Pod 삭제 관찰 → AWS 구현 연결 순서로 확장한다. AWS 실습에서는 실행 시점의 공식 문서와 계정·권한·비용 조건을 확인해 별도 환경을 준비한다.

처음부터 Service Mesh, 멀티클러스터, 커스텀 controller, GPU·AI/ML까지 동시에 배우지 않는다. **현재 그림에서 설명할 수 없는 화살표 하나를 골라 필요한 원문만 읽는 방식**으로 깊이를 늘린다.
