# Kubernetes · EKS 심화: 선언부터 장애 복구까지

이 교재의 목표는 **설정을 읽고, 내부 동작을 예측하고, 관측 결과로 문제의 위치를 좁히는 능력**이다. 처음에는 쉬운 설명으로 시작하지만, 마지막에는 배포 실패·네트워크 장애·권한 오류·용량 부족을 서로 구분할 수 있도록 구성했다.

기존 [전체 배포 흐름](../../01_기초/06_Git에서_EKS까지_전체_배포_흐름.md)이 지도라면, 이 폴더는 지도 속 각 구간을 확대해서 읽는 책이다. 모든 API 필드를 외우는 대신 반복해서 사용하는 원리를 익힌다. 읽기만으로 운영 숙련이 완성되지는 않으므로, 예측 → 실습 → 설명의 과정을 포함했다.

## 책 전체를 관통하는 예시

`orders`라는 주문 API를 운영한다고 가정한다. 이미지는 레지스트리에 있고, 앱은 8080 포트에서 요청을 받는다. 처음에는 Pod 두 개로 시작해 외부 접속, 데이터 저장, 권한, 자동 확장, 장애 복구를 하나씩 붙인다. 실습 앱은 이 구조를 관찰하기 위한 작은 HTTP 서버이며 실제 주문·결제 기능은 없다.

매번 다음 다섯 질문을 던진다.

1. **어떤 문제를 해결하려는가?** 예: Pod가 교체되어 주소가 달라진다.
2. **어느 오브젝트에 의도를 쓰는가?** 예: Service의 selector와 port.
3. **어느 프로그램이 관찰하는가?** 예: EndpointSlice controller와 kube-proxy.
4. **실제로 무엇이 바뀌는가?** 예: 대상 목록과 노드의 패킷 전달 규칙.
5. **어떻게 확인하는가?** 예: EndpointSlice, 실제 연결, controller 로그.

## 전제와 자료 사용법

기본 설명은 Linux 컨테이너와 일반 Kubernetes, AWS 설명은 **EKS + EC2 Managed Node Group + Amazon VPC CNI + AWS Load Balancer Controller**다. ALB 그림은 별도 표시가 없으면 IP target 방식이다. Auto Mode·Fargate·다른 CNI는 차이를 분리해서 설명한다.

그림에서 실선은 요청·생성·전달, 점선은 관찰·참조를 뜻한다. 소유 관계는 `소유`라고 표시한다. 모든 그림에 프로그램과 객체를 동시에 펼치지는 않으므로, 논리적인 생성 관계와 실제 API 통신을 구분하는 설명을 함께 읽는다.

기존 PDF 분석을 토대로 새로 집필하고, 변경 가능성이 큰 EKS 기능과 Kubernetes 동작은 공식 문서로 대조했다. **공식 문서 확인일: 2026-09-06.** 공식 Kubernetes 사이트의 최신 기능이 EKS의 모든 지원 버전에 들어 있는 것은 아니다. 설치·업그레이드 때는 자신의 클러스터 버전과 add-on 호환표를 확인한다. 원문 지도와 범위는 13장에 있다.

예제 파일은 [실습 폴더](../../02_심화/실습/README.md)에 있다. 이 집필 과정에서 AWS 자원 생성이나 클러스터 변경은 수행하지 않았다. 문서의 실습 명령은 학습자가 선택한 별도 실습 환경에서 실행한다.
