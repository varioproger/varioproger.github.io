# 1장. 시작하며: 왜 프로그래머가 OS를 알아야 하는가

## 1.1 "동작한다"와 "이해한다"의 차이

다음과 같은 질문에 바로 답할 수 있는가?

- 스레드를 10개 만들면 정말 10개의 CPU 코어에서 동시에 도는가?
- `malloc(100MB)`를 호출했는데 왜 물리 메모리는 그대로인가?
- 프로세스를 강제로 죽였는데 왜 포트가 몇 초간 안 풀리는가?
- 파일을 읽었다가 지웠는데 디스크 용량이 안 줄어드는 이유는?
- 스레드가 4개인 프로그램이 CPU 코어 1개짜리 VM에서는 왜 이상하게 느려지는가?

이 질문들의 답은 라이브러리 문서에 없다. **OS가 그 뒤에서 무엇을 하고 있는지**를 알아야 답할 수 있다. 이 책은 바로 이런 "코드는 짜지만 그 아래에서 무슨 일이 벌어지는지는 모르는" 간극을 메우기 위한 것이다.

## 1.2 OS 지식이 실제로 쓰이는 곳

| 상황 | 필요한 지식 |
|---|---|
| 서버가 메모리를 계속 늘려 먹다가 OOM으로 죽는다 | 가상 메모리, 힙 관리, 메모리 매핑 ([5장](05_메모리.md)) |
| 멀티스레드 프로그램이 가끔 멈추거나 결과가 다르다 | 동기화, 캐시 가시성, 메모리 모델 ([4장](04_스레드와_동시성.md)) |
| 초당 수만 커넥션을 처리하는 서버를 만들어야 한다 | 비동기 I/O, IOCP/epoll ([6장](06_네트워크.md)) |
| 프로세스를 강제로 죽였는데 포트가 몇 초간 안 풀린다 | TIME_WAIT, 소켓 재사용 ([6장](06_네트워크.md)) |
| "프로세스 fork 비용이 왜 이렇게 크지?" | 프로세스/주소 공간, COW ([3장](03_프로세스.md)) |
| 배포 후 CPU 사용률이 이상하게 튄다 | 스케줄러, 컨텍스트 스위칭 ([2장](02_OS_큰그림.md), [4장](04_스레드와_동시성.md)) |
| 로그 파일 쓰기가 갑자기 블로킹된다 | 파일 캐시, 버퍼링, fsync ([7장](07_파일시스템과_IO.md)) |

## 1.3 이 책의 관점: "커널이 나 대신 해주는 일"

프로그래머 입장에서 OS는 **하드웨어를 흉내 내는 거대한 라이브러리**다. 커널은 다음을 대신 해준다.

1. **CPU 시분할** — 코어보다 많은 프로세스/스레드를 동시에 실행하는 것처럼 보이게 함
2. **메모리 가상화** — 모든 프로세스가 독립된 4GB/128TB 주소 공간을 가진 것처럼 착각하게 함
3. **자원 중재** — 여러 프로그램이 같은 디스크, 같은 네트워크 카드를 동시에 써도 안전하게 만듦
4. **격리와 보호** — 한 프로그램의 버그가 다른 프로그램이나 커널 자체를 건드리지 못하게 막음

이 네 가지 축("시분할", "메모리 가상화", "자원 중재", "격리")을 기억하면, 이 책 전체가 이 네 가지를 각기 다른 단면에서 설명하는 것임을 알 수 있다.

## 1.4 용어 안내: Windows와 리눅스

이 책은 Windows 참고서(*Windows Internals*, *Windows via C/C++*)를 기반으로 하므로 Windows 용어를 기본으로 쓰지만, 대부분의 개념은 리눅스/POSIX에도 대응 개념이 있다. 각 장 끝에 대응표를 둔다. 미리 감을 잡자면:

| Windows | Linux/POSIX | 의미 |
|---|---|---|
| 프로세스(Process), 핸들(Handle) | 프로세스, 파일 디스크립터(fd) | 실행 중인 프로그램과 자원 참조자 |
| 스레드(Thread) | 스레드(pthread) | 실행 흐름의 단위 |
| 가상 주소 공간(Virtual Address Space) | 가상 주소 공간 | 프로세스별 독립 메모리 뷰 |
| CreateFile/ReadFile | open/read | 파일 I/O |
| IOCP (I/O Completion Port) | epoll / io_uring | 확장 가능한 비동기 I/O |
| SRWLock, CRITICAL_SECTION | pthread_mutex, futex | 동기화 프리미티브 |

다음 장부터는 커널/유저 모드 전환, 시스템 콜, 스케줄러라는 "OS의 큰 그림"부터 시작한다.
