# 부록 H. AWS 보안 자격증(SCS-C02) 시험 범위 매핑

이 부록은 **이 책의 본문을 시험 준비용으로 재배열한 색인**입니다. 시험 문제를 대신 풀어 주는 문제집이 아니라, "이 주제가 나오면 본서 어느 절로 돌아가야 하는가"를 알려 주는 지도입니다.

---

## H.1 이 부록의 사용법과 ⚠️ 주의

> ⚠️ **가장 먼저 읽을 것 — 시험 가이드는 개정됩니다.**
>
> AWS는 시험 가이드(Exam Guide)를 주기적으로 개정합니다. 도메인의 명칭과 구분, 각 도메인의 **가중치**, **문항 수**, **시험 시간**, **합격 기준**, 출제 대상 서비스 목록은 모두 개정 대상입니다.
>
> **이 부록은 그 값들을 적지 않습니다.** 책에 적어두는 순간 낡기 때문이고, 낡은 값을 믿고 준비 계획을 세우는 것이 준비 실패의 가장 흔한 원인이기 때문입니다.
>
> 🔴 **반드시 AWS 공식 시험 가이드(Exam Guide) 최신판을 직접 내려받아 확인하십시오.** 아래 두 가지를 반드시 본인이 확인한 값으로 채워 넣고 시작하십시오.
>
> - 시험 운영 조건 — 문항 수, 시험 시간, 채점 방식, 합격 기준, 응시 언어
> - 도메인 구성 — 도메인 명칭과 개수, 각 도메인의 가중치, 도메인별 과제 진술(task statement)과 대상 지식·기술
>
> 이 부록이 제공하는 것은 그 위에 얹는 **본문 매핑**입니다. 도메인 구성이 개정되더라도 "무엇을 알아야 하는가"라는 주제 자체는 크게 변하지 않으므로, 매핑은 개정과 무관하게 유효합니다.

### 도메인 구성에 대하여

집필 시점에 일반적으로 알려진 SCS-C02의 출제 범위는 아래 **여섯 가지 성격의 영역**으로 나뉩니다. 이 책은 아래 순서가 아니라 **아키텍처를 쌓는 순서**로 쓰였으므로, 도메인과 장 번호는 일대일로 대응하지 않습니다.

| # | 영역 | 이 영역의 질문이 묻는 것 | 본서 주력 부 | 비중(정성) |
|---|---|---|---|---|
| **D1** | 위협 탐지와 사고 대응 영역 | 이상 징후를 어떻게 알아채고, 알아챈 뒤 무엇을 먼저 하는가 | 6부 (29~35장) | 높음 |
| **D2** | 보안 로깅과 모니터링 영역 | 무엇을 어디에 기록하고, 기록된 것을 어떻게 질의·경보하는가 | 6부 (29~30장) | 높음 |

> ⚠️ **"비중(정성)" 열은 공식 가중치가 아닙니다.** 출제 범위 전반을 보았을 때 학습 분량이 상대적으로 어느 정도인지에 대한 **집필자의 정성적 판단**일 뿐입니다. 실제 배분은 공식 시험 가이드의 수치를 확인해서 쓰십시오. 그리고 **어느 도메인도 버릴 수 없습니다** — 여섯 영역이 서로 물려 있어 한 영역을 비우면 다른 영역 문제도 틀립니다.

### 시험 문제의 두 가지 성격

이 시험 문제는 크게 두 부류입니다. 준비 방법이 다릅니다.

| 유형 | 전형적 질문 | 준비 방법 |
|---|---|---|
| **판정형** | "정책 A와 B가 함께 걸렸을 때 이 호출은 허용되는가" | 규칙을 **암기 수준으로** 정확히 알아야 합니다. H.3이 이 유형입니다 |
| **선택형** | "요구사항이 이러할 때 무엇을 써야 하는가" | 서비스 간 **선택 기준**을 알아야 합니다. H.4와 부록 G.4가 이 유형입니다 |

🔴 **판정형에서 "대체로 이럴 것이다"는 통하지 않습니다.** 0.2의 트랙 D가 짚은 세 절 — **7.3(정책 평가 순서) · 13.4(키 정책과 IAM의 결합 평가) · 15.1(S3 4중 구조)** — 은 문장 단위로 정확히 재현할 수 있을 때까지 반복하십시오.

## H.3 시험에 특히 잘 나오는 개념 25선

이 25개는 **판정형 문제의 정답 근거**가 되는 규칙들입니다. "이럴 것 같다"로는 틀립니다.

| # | 개념 | 왜 자주 나오나 | 본문 |
|---|---|---|---|
| 1 | **정책 평가 순서** | 여러 정책이 겹친 상황을 주고 결과를 묻는 유형의 뼈대. 명시적 Deny가 모든 것을 이기고, 암묵적 Deny는 허용으로 뒤집힌다는 차이가 핵심 | 7.3 |
| 2 | **SCP는 권한을 부여하지 않는다** | "SCP에 Allow가 있으니 된다"는 오답을 유도하기 쉬움. SCP는 **상한**이고 실제 부여는 IAM이 한다 | 37.1, 37.3 |
| 3 | **키 정책 없이는 KMS 접근 불가** | IAM 전체 권한을 가진 관리자도 키 정책이 계정에 위임하지 않으면 키를 쓸 수 없다 | 13.4 |
| 4 | **크로스 계정은 양쪽 허용이 필요** | 리소스 쪽 정책(신뢰 정책·버킷 정책·키 정책)과 호출자 쪽 IAM 정책이 **모두** 허용해야 한다 | 8.5, 15.5, 13.10 |
| 5 | **보안 그룹은 상태 저장, NACL은 상태 비저장** | "응답이 왜 안 오는가" 유형의 정답이 대부분 NACL 아웃바운드 임시 포트 | 19.1 |
| 6 | **보안 그룹에는 거부 규칙이 없다** | 특정 IP만 차단하려면 NACL이나 상위 계층이어야 한다 | 19.1, 19.3 |
| 7 | **퍼블릭/프라이빗을 가르는 것은 라우팅 테이블** | 서브넷 이름이나 태그가 아니라 IGW 경로 유무가 판정 기준 | 18.4 |
| 8 | **VPC 엔드포인트 정책** | 엔드포인트를 뚫는 것과 그 엔드포인트로 나가는 요청을 제한하는 것은 별개. 데이터 유출 차단 문제의 정답 | 20.3 |
| 9 | **게이트웨이 엔드포인트는 온프레미스에서 쓸 수 없다** | 하이브리드 환경에서 S3 프라이빗 접근을 묻는 문제의 분기점 | 20.1, 20.2 |
| 10 | **IMDSv2** | SSRF 시나리오에서 "무엇을 켜야 하는가"의 표준 정답. 홉 제한이 컨테이너 경로를 닫는다 | 8.3 |
| 11 | **Confused Deputy와 External ID** | 서드파티 SaaS에 역할을 부여하는 시나리오의 고정 출제 지점 | 8.6 |
| 12 | **S3 퍼블릭 액세스 차단의 우선순위** | 버킷 정책이 퍼블릭을 허용해도 BPA가 켜져 있으면 차단된다 | 15.2, 15.1 |
| 13 | **객체 잠금 두 모드의 차이** | 거버넌스는 특별 권한으로 해제 가능, 컴플라이언스는 **루트도 불가**. 랜섬웨어·감사 문제의 정답 | 15.9 |
| 14 | **버전 관리는 비활성화할 수 없다** | 한 번 켜면 중지(suspend)만 가능하다는 점, MFA Delete가 무엇을 요구하는지 | 15.8 |
| 15 | **사전 서명 URL은 서명자의 권한을 상속한다** | 만든 사람의 권한이 사라지면 URL도 죽고, 강한 주체가 만들면 강한 URL이 된다 | 15.6 |
| 16 | **CloudTrail 데이터 이벤트는 기본 꺼져 있다** | "S3에서 누가 객체를 가져갔는지 모른다"의 원인이자 정답 | 29.2, 15.11 |
| 17 | **조직 트레일은 멤버가 끌 수 없다** | 로그 무력화 시나리오에서 올바른 구성으로 제시되는 항목 | 29.4, 29.9 |
| 18 | **로그 파일 무결성 검증과 객체 잠금** | "로그가 변조되지 않았음을 어떻게 증명하나"의 두 축 | 29.3 |
| 19 | **GuardDuty의 데이터 소스** | 어떤 로그를 켜야 무엇이 탐지되는지, 에이전트가 필요한 항목과 아닌 항목 | 31.1 |
| 20 | **GuardDuty·Security Hub의 위임 관리자** | 다계정 집계 구성 문제의 정답. 관리 계정에서 직접 돌리지 않는다 | 31.2, 36.6 |
| 21 | **ACM 인증서의 리전 제약** | CloudFront에 붙일 인증서는 다른 리전에서 발급해야 한다는 점이 반복 출제 | 23.2 |
| 22 | **TLS 종료 위치가 바꾸는 것** | 어디서 끊느냐에 따라 WAF 적용 지점과 내부 구간 암호화 여부가 달라진다 | 23.5, 23.6 |
| 23 | **암호화 스냅샷 공유에는 키 권한이 따라가야 한다** | 스냅샷·AMI 공유 시나리오에서 "왜 상대가 못 쓰는가"의 정답 | 16.7, 13.10 |
| 24 | **태스크 역할과 태스크 실행 역할의 분리** | ECS 문제에서 "어느 역할에 권한을 주어야 하는가"로 자주 나온다 | 24.3 |
| 25 | **임시 자격 증명은 즉시 회수할 수 없다** | 유출 대응 문제에서 "키 삭제"가 오답이 되는 이유. 역할에 Deny를 붙이는 것이 정답 | 6.3, 33.3 |

## H.4 헷갈리는 서비스 비교표 10개

부록 G.4가 **"둘이 어떻게 다른가"** 를 다뤘다면, 여기는 **"요구사항이 이럴 때 무엇을 고르는가"** 입니다. 시험의 선택형 문제는 거의 이 형태로 나옵니다.

### ① 키 관리 — KMS vs CloudHSM vs 외부 키 스토어(XKS)

| 요구사항 | 선택 | 근거 | 본문 |
|---|---|---|---|
| 일반적인 저장 암호화, AWS 서비스 통합 | **KMS** | 대부분의 서비스가 KMS와 직접 통합되고 운영 부담이 없음 | 13.3 |
| 단독 테넌시 HSM, 상위 FIPS 검증 요건 | **CloudHSM** | 하드웨어를 공유하지 않는다는 요건은 KMS로 충족 불가 | 14.1 |
| PKCS#11 등 표준 인터페이스로 직접 연동 | **CloudHSM** | 애플리케이션이 HSM API를 직접 호출해야 하는 경우 | 14.2 |
| 키 자료를 AWS 밖에 두어야 하는 규제 | **외부 키 스토어(XKS)** | 키 자료가 AWS에 존재하지 않아야 한다는 요구의 유일한 답 | 14.4 |
| 키 자료를 우리가 생성해 가져와야 함 | **KMS + BYOK** | 가져온 키 자료는 만료·재가져오기 관리가 따라붙음 | 14.5 |

### ② 무엇을 탐지하나 — GuardDuty vs Inspector vs Macie vs Config

| 찾고 싶은 것 | 선택 | 근거 | 본문 |
|---|---|---|---|
| 이상 행위·악성 통신·비정상 API 호출 | **GuardDuty** | 로그를 분석해 **행위**를 본다 | 31.1 |
| 워크로드의 알려진 취약점(CVE) | **Inspector** | EC2·ECR·Lambda의 **소프트웨어 목록**을 본다 | 26.3 |
| S3에 민감 데이터가 있는지 | **Macie** | 객체 **내용**을 본다 | 12.4, 31.3 |
| 리소스 설정이 기준에서 벗어났는지 | **AWS Config** | 리소스 **구성**을 본다 | 29.8 |
| 정책이 외부에 접근을 열었는지 | **IAM Access Analyzer** | **정책**을 본다 | 7.7 |

### ③ 결과를 어디에 모으나 — Security Hub vs Detective vs Security Lake

| 목적 | 선택 | 근거 | 본문 |
|---|---|---|---|
| 여러 보안 서비스 결과를 한 화면에서 처리 | **Security Hub** | 결과 정규화(ASFF)와 표준 컨트롤 평가가 목적 | 31.5 |
| 하나의 사건을 파고들어 연결 관계를 추적 | **Detective** | 로그를 행동 그래프로 묶어 조사 동선을 제공 | 31.4 |
| 원본 로그를 장기 보관하고 자유롭게 질의 | **Security Lake** | 조직 전체 로그를 개방 스키마로 적재 | 30.7 |
| 즉석 질의만 필요하고 적재 체계는 불필요 | **Athena** | S3에 이미 있는 로그를 그대로 SQL로 조회 | 30.6 |

### ④ 어떤 로그를 켜나 — CloudTrail vs 플로우 로그 vs 액세스 로그

| 답해야 하는 질문 | 선택 | 근거 | 본문 |
|---|---|---|---|
| 누가 어떤 AWS API를 호출했나 | **CloudTrail 관리 이벤트** | 제어 평면 감사 | 29.2 |
| 누가 어떤 객체를 읽고 썼나 | **CloudTrail 데이터 이벤트** | 데이터 평면. 기본 꺼져 있고 유료 | 29.2, 15.11 |
| 어떤 IP가 어떤 포트로 연결을 시도했나 | **VPC 플로우 로그** | 메타데이터만. 페이로드는 없음 | 29.5 |
| 애플리케이션이 무엇을 기록했나 | **CloudWatch Logs** | 에이전트로 수집. 보존 기간을 반드시 지정 | 29.6, 29.7 |

### ⑤ TLS를 어디서 끊나 — CloudFront vs ALB vs NLB vs 인스턴스

| 요구사항 | 선택 | 근거 | 본문 |
|---|---|---|---|
| 엣지 캐싱과 WAF를 함께 적용 | **CloudFront** | 가장 앞단에서 끊고 오리진으로 재암호화 | 23.7 |
| HTTP 계층 라우팅·인증·WAF 부착 | **ALB** | L7 처리와 WAF 연결이 가능한 지점 | 23.3, 23.8 |
| 클라이언트 인증서를 앱이 직접 검증해야 함 | **NLB 패스스루** 또는 **ALB mTLS** | 종단 간 TLS가 필요한 경우 | 23.5 |
| 규제상 종단 간 암호화가 강제됨 | **인스턴스에서 종료** | 중간에서 평문이 되는 구간이 없어야 할 때 | 23.5 |
| 신규 구성 | **CLB는 쓰지 않는다** | 이전 세대. WAF 연결과 최신 TLS 정책 불가 | 23.3 |

### ⑥ 어느 계층에서 막나 — WAF vs Shield vs Network Firewall vs NACL

| 막고 싶은 것 | 선택 | 근거 | 본문 |
|---|---|---|---|
| SQL 인젝션·봇·요청 폭주 | **AWS WAF** | HTTP 요청 내용을 검사 | 23.8 |
| 대규모 볼류메트릭 DDoS | **Shield** | 네트워크·전송 계층 공격 흡수 | 23.10 |
| 아웃바운드 도메인·SNI 통제, IPS 성격 | **Network Firewall** | 상태 저장 검사와 도메인 필터링 | 19.5, 19.6 |
| 특정 IP 대역을 서브넷 경계에서 차단 | **NACL** | 보안 그룹에는 거부 규칙이 없음 | 19.1, 19.4 |
| 조직 전체에 동일 규칙을 강제 | **Firewall Manager** | 계정마다 붙이는 대신 중앙에서 배포·감사 | 23.11 |

### ⑦ 온프레미스를 어떻게 잇나 — VPN vs Direct Connect vs TGW vs 피어링

| 요구사항 | 선택 | 근거 | 본문 |
|---|---|---|---|
| 빠르게, 저비용으로, 암호화된 연결 | **Site-to-Site VPN** | IPsec 터널. 대역폭·지연은 인터넷에 의존 | 21.1 |
| 안정적 대역폭·낮은 지연 | **Direct Connect** | 전용 회선. **암호화는 별도로 얹어야 함** | 21.2 |
| VPC가 여러 개이고 계속 늘어남 | **Transit Gateway** | 허브 구조와 라우팅 테이블 단위 격리 | 21.3 |
| VPC 두 개만, 단순 연결 | **VPC 피어링** | 전이 라우팅이 안 되므로 확장에는 부적합 | 21.4 |

### ⑧ 관리 접근을 어떻게 주나 — Session Manager vs 배스천 vs VPN

| 요구사항 | 선택 | 근거 | 본문 |
|---|---|---|---|
| 인바운드 포트를 열지 않고 셸 접근 | **Session Manager** | 아웃바운드만으로 동작, IAM으로 인가 | 21.6 |
| 세션 내용을 기록·감사해야 함 | **Session Manager** | 세션 로그를 S3·CloudWatch로 전송 | 21.6 |
| 레거시 프로토콜·GUI가 필요 | **배스천 호스트(제한적)** | 여전히 필요할 수 있으나 공격 표면이 늘어남 | 21.5 |
| 온프레미스 관리망에서 사설 IP로 접근 | **Site-to-Site VPN / DX** | 네트워크 경로 자체가 필요한 경우 | 21.1, 21.2 |

### ⑨ 불변 보존을 어떻게 거나 — S3 Object Lock vs Glacier Vault Lock vs Backup Vault Lock

| 대상 | 선택 | 근거 | 본문 |
|---|---|---|---|
| S3 객체(로그·문서·아티팩트) | **S3 Object Lock** | 현재의 사실상 표준. 버전 관리 필수 | 15.9 |
| 이미 Glacier 볼트에 있는 자산 | **Glacier Vault Lock** | 24시간 안에 검증·완료해야 잠김 | 16.5 |
| AWS 리소스 백업(EBS·RDS·EFS 등) | **AWS Backup Vault Lock** | 볼트 단위로 같은 모델 제공 | 17.3 |
| 원본 계정이 완전히 소실되는 시나리오 | **백업 계정 분리 + 볼트 잠금** | 같은 계정 안의 백업은 대비가 아님 | 17.4, 17.5 |

### ⑩ 랜딩 존을 어떻게 만드나 — Control Tower vs 커스텀

| 상황 | 선택 | 근거 | 본문 |
|---|---|---|---|
| 표준 구성으로 빠르게 시작 | **Control Tower** | 계정 구조·로깅·가드레일을 관리형으로 제공 | 37.5 |
| 기존 조직·기존 계정이 이미 복잡 | **커스텀 랜딩 존** | 관리형 전제와 충돌하는 요구가 있을 때 | 37.6 |
| 신규 계정에 통제를 자동으로 심기 | **StackSets 베이스라인** | 어느 쪽을 고르든 이 부분은 필요 | 37.9 |
| 조직 전체 규칙 평가 | **Config 적합성 팩** | 가드레일의 탐지 축 | 37.7 |

> ⚠️ **누구를 인증하는가**로 갈리는 문제도 자주 나옵니다. 직원의 AWS 접근은 **IAM Identity Center**(9.2), 고객의 애플리케이션 로그인은 **Cognito**(10.1), 워크로드는 **역할**(8.2, 8.8)입니다. IAM 사용자는 "Identity Center를 쓸 수 없는 예외"로만 남습니다(6.4).

## H.6 이 책이 다루지 않는 시험 범위

⚠️ **정직하게 말하면, 이 책만으로 시험 준비가 끝나지 않습니다.** 이 책은 보안 **아키텍처** 책이고, 시험은 아키텍처 외에 운영 절차와 시험 특유의 문제 형식을 함께 묻습니다. 아래는 따로 보아야 하는 것들입니다.

| 다루지 않는 것 | 왜 빠졌나 | 무엇으로 보충하나 |
|---|---|---|
| **시험 운영 정보** (문항 수, 시험 시간, 채점·합격 기준, 응시 규정) | 개정 대상이어서 의도적으로 적지 않음 | 🔴 **AWS 공식 시험 가이드 최신판** |
| **도메인별 과제 진술(task statement)의 정확한 문구** | 개정 대상 | 🔴 **AWS 공식 시험 가이드 최신판** |
| **콘솔 화면 클릭 순서** | 화면은 자주 바뀌므로 이 책은 CLI·API 파라미터 기준으로 서술 | AWS 공식 문서, 직접 실습 |
| **서비스별 한도(quota)와 세부 사양** | 수치가 자주 바뀌고 암기 대상이 아님 | AWS 서비스별 문서의 Quotas 페이지 |
| **서비스별 API·CLI 레퍼런스 전수** | 책의 목적이 아님. 본문은 보안에 걸리는 파라미터만 다룸 | AWS CLI Reference, API Reference |
| **문제 풀이 훈련과 시간 배분 감각** | 문제집이 아님 | 🔴 **AWS 공식 연습 문제 세트와 모의고사**. 최소 2회는 실전 조건으로 |
| **오답 선택지 읽는 요령** | 시험 특유의 기술 | 모의고사 복기. "왜 이것이 오답인가"를 매 문항 적을 것 |
| **일부 서비스의 세부 운영 절차** (예: 특정 서비스의 마이그레이션·업그레이드 절차) | 보안 아키텍처와 직접 관련이 낮음 | AWS 공식 문서, 해당 서비스 워크숍 |
| **온프레미스 보안 제품과의 연동 상세** | 제품 종속적 | 벤더 문서 |
| **AWS 공식 교육 과정** | 별개 자료 | AWS Skill Builder의 해당 과정과 램프업 가이드 |

### 이 책이 시험 준비에서 갖는 위치

| 이 책이 해 주는 것 | 이 책이 못 해 주는 것 |
