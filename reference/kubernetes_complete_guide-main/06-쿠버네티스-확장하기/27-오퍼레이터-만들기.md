# 27장. 오퍼레이터 만들기

> **학습목표**
> - 코드 생성이 무엇을 만들어 주고 왜 필요한지 안다.
> - Kubebuilder로 프로젝트를 스캐폴딩하고 CRD를 정의할 수 있다.
> - controller-runtime의 조정 함수를 올바르게 작성할 수 있다.
> - 소유 리소스 관리, 파이널라이저, status 갱신을 구현할 수 있다.
> - 조정 루프의 원칙(멱등성, 에러 처리, 관측성)을 적용할 수 있다.
> - Go 외의 접근법도 상황에 따라 선택할 수 있다.

---

## 들어가며

25장에서 컨트롤러를 저수준으로 만들었고, 26장에서 CRD를 정의했다. 이제 둘을 합친다.

**저수준 구현의 문제**는 보일러플레이트가 많다는 것이다. Informer 설정, 워크큐 관리, 캐시 동기화, 리더 선출, 메트릭... 도메인 로직은 전체의 10%도 되지 않는다.

**controller-runtime**이 이것을 해결한다. Kubebuilder는 그 위에 스캐폴딩을 얹은 도구다.

## 27.1 코드 생성

### 무엇을 생성하는가

커스텀 타입을 쿠버네티스 생태계에서 쓰려면 여러 코드가 필요하다.

| 생성물 | 역할 | 도구 |
|---|---|---|
| `zz_generated.deepcopy.go` | `DeepCopyObject()` 구현 | controller-gen |
| CRD 매니페스트 | Go 타입 → OpenAPI 스키마 | controller-gen |
| RBAC 매니페스트 | 마커 → Role/ClusterRole | controller-gen |
| ClientSet, Lister, Informer | 타입별 클라이언트 (저수준 방식) | code-generator |

**DeepCopy가 필수인 이유**: 25.4절에서 본 캐시 오염 문제 때문이다. `runtime.Object` 인터페이스가 `DeepCopyObject()`를 요구한다.

### 마커(marker) 주석

**Go 주석이 생성기의 입력이 된다.**

```go
// +kubebuilder:object:root=true
// +kubebuilder:subresource:status
// +kubebuilder:subresource:scale:specpath=.spec.replicas,statuspath=.status.readyReplicas,selectorpath=.status.selector
// +kubebuilder:resource:shortName=wa,categories=all
// +kubebuilder:printcolumn:name="Image",type=string,JSONPath=`.spec.image`
// +kubebuilder:printcolumn:name="Ready",type=integer,JSONPath=`.status.readyReplicas`
// +kubebuilder:printcolumn:name="Age",type=date,JSONPath=`.metadata.creationTimestamp`
type WebApp struct {
    metav1.TypeMeta   `json:",inline"`
    metav1.ObjectMeta `json:"metadata,omitempty"`
    Spec   WebAppSpec   `json:"spec,omitempty"`
    Status WebAppStatus `json:"status,omitempty"`
}

type WebAppSpec struct {
    // +kubebuilder:validation:Required
    // +kubebuilder:validation:MinLength=1
    // +kubebuilder:validation:Pattern=`^[a-z0-9.\-/]+:[a-zA-Z0-9._\-]+$`
    Image string `json:"image"`

    // +kubebuilder:validation:Minimum=0
    // +kubebuilder:validation:Maximum=50
    // +kubebuilder:default=1
    // +optional
    Replicas *int32 `json:"replicas,omitempty"`

    // +kubebuilder:validation:Enum=dev;staging;production
    // +kubebuilder:default=dev
    // +optional
    Tier string `json:"tier,omitempty"`
}
```

**26장에서 YAML로 쓴 스키마가 Go 마커로 표현된다.** `make manifests`를 실행하면 26.7절과 같은 CRD YAML이 생성된다.

**두 소스를 동기화할 필요가 없다는 것이 큰 이점이다.** Go 타입이 진실의 원천이 된다.

### 두 가지 방식

| | **code-generator** (저수준) | **controller-runtime** (권장) |
|---|---|---|
| 생성물 | ClientSet, Lister, Informer, DeepCopy | DeepCopy, CRD, RBAC |
| 클라이언트 | 타입별 생성된 클라이언트 | 범용 `client.Client` |
| 코드량 | 많음 | 적음 |
| 학습 곡선 | 가파름 | 완만함 |
| 쓰이는 곳 | 쿠버네티스 본체, 오래된 프로젝트 | 대부분의 새 프로젝트 |

**이 장은 controller-runtime을 기준으로 한다.** 저수준 방식은 27.2절에서 개요만 다룬다.

## 27.2 sample-controller — 저수준 방식 개요

쿠버네티스 프로젝트가 제공하는 참조 구현이다. **읽어 볼 가치는 있지만 새로 만들 때 이 방식을 쓸 이유는 거의 없다.**

```bash
git clone https://github.com/kubernetes/sample-controller
cd sample-controller
```

**구조**

```
pkg/apis/samplecontroller/v1alpha1/
    types.go              ← 타입 정의
    register.go           ← Scheme 등록
    zz_generated.deepcopy.go
pkg/generated/            ← code-generator가 만든 것
    clientset/
    informers/
    listers/
controller.go             ← 25장에서 만든 것과 유사한 구조
main.go
hack/update-codegen.sh    ← 코드 생성 스크립트
```

**핵심 로직**은 25.5절에서 만든 것과 같다.

```go
func (c *Controller) syncHandler(key string) error {
    namespace, name, _ := cache.SplitMetaNamespaceKey(key)

    foo, err := c.foosLister.Foos(namespace).Get(name)
    if errors.IsNotFound(err) {
        return nil
    }

    deploymentName := foo.Spec.DeploymentName
    deployment, err := c.deploymentsLister.Deployments(namespace).Get(deploymentName)
    if errors.IsNotFound(err) {
        deployment, err = c.kubeclientset.AppsV1().Deployments(namespace).
            Create(context.TODO(), newDeployment(foo), metav1.CreateOptions{})
    }
    if err != nil {
        return err
    }

    // ★ 소유권 확인 — 남의 것을 건드리지 않는다
    if !metav1.IsControlledBy(deployment, foo) {
        msg := fmt.Sprintf("Resource %q already exists and is not managed by Foo", deployment.Name)
        c.recorder.Event(foo, corev1.EventTypeWarning, "ErrResourceExists", msg)
        return fmt.Errorf("%s", msg)
    }

    // 원하는 replicas와 다르면 갱신
    if foo.Spec.Replicas != nil && *foo.Spec.Replicas != *deployment.Spec.Replicas {
        deployment, err = c.kubeclientset.AppsV1().Deployments(namespace).
            Update(context.TODO(), newDeployment(foo), metav1.UpdateOptions{})
    }
    if err != nil {
        return err
    }

    return c.updateFooStatus(foo, deployment)
}
```

**주목할 점**: `metav1.IsControlledBy` 확인이다. 같은 이름의 Deployment가 이미 있는데 다른 소유자의 것이라면 **건드리면 안 된다.** 이 확인을 빠뜨리면 심각한 사고가 난다.

**저수준 방식을 쓸 만한 경우**
- 쿠버네티스 본체에 기여할 때
- controller-runtime의 추상화가 방해가 되는 특수 요구
- 극도로 성능이 중요한 경우

**나머지 모든 경우에는 controller-runtime을 쓴다.**

### 조정 함수 구현

```go
// internal/controller/webapp_controller.go
package controller

import (
    "context"
    "fmt"

    appsv1 "k8s.io/api/apps/v1"
    corev1 "k8s.io/api/core/v1"
    apierrors "k8s.io/apimachinery/pkg/api/errors"
    "k8s.io/apimachinery/pkg/api/meta"
    metav1 "k8s.io/apimachinery/pkg/apis/meta/v1"
    "k8s.io/apimachinery/pkg/runtime"
    "k8s.io/apimachinery/pkg/types"
    "k8s.io/apimachinery/pkg/util/intstr"
    "k8s.io/client-go/tools/record"
    "k8s.io/utils/ptr"
    ctrl "sigs.k8s.io/controller-runtime"
    "sigs.k8s.io/controller-runtime/pkg/client"
    "sigs.k8s.io/controller-runtime/pkg/log"

    demov1 "example.com/webapp-operator/api/v1"
)

const finalizerName = "demo.example.com/finalizer"

type WebAppReconciler struct {
    client.Client
    Scheme   *runtime.Scheme
    Recorder record.EventRecorder
}

// ★ 마커가 RBAC 매니페스트를 생성한다 (17.3절)
// +kubebuilder:rbac:groups=demo.example.com,resources=webapps,verbs=get;list;watch;create;update;patch;delete
// +kubebuilder:rbac:groups=demo.example.com,resources=webapps/status,verbs=get;update;patch
// +kubebuilder:rbac:groups=demo.example.com,resources=webapps/finalizers,verbs=update
// +kubebuilder:rbac:groups=apps,resources=deployments,verbs=get;list;watch;create;update;patch;delete
// +kubebuilder:rbac:groups="",resources=services,verbs=get;list;watch;create;update;patch;delete
// +kubebuilder:rbac:groups="",resources=events,verbs=create;patch

func (r *WebAppReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {
    logger := log.FromContext(ctx)

    // ① 현재 상태를 읽는다
    var app demov1.WebApp
    if err := r.Get(ctx, req.NamespacedName, &app); err != nil {
        // NotFound는 정상 — 삭제된 것이다
        return ctrl.Result{}, client.IgnoreNotFound(err)
    }

    // ② 삭제 중인가? (4.2절의 파이널라이저)
    if !app.DeletionTimestamp.IsZero() {
        return r.reconcileDelete(ctx, &app)
    }

    // ③ 파이널라이저 등록
    if !controllerutil.ContainsFinalizer(&app, finalizerName) {
        controllerutil.AddFinalizer(&app, finalizerName)
        if err := r.Update(ctx, &app); err != nil {
            return ctrl.Result{}, err
        }
    }

    // ④ Deployment 조정
    deploy, err := r.reconcileDeployment(ctx, &app)
    if err != nil {
        r.setCondition(&app, "Ready", metav1.ConditionFalse, "DeploymentFailed", err.Error())
        _ = r.updateStatus(ctx, &app)
        return ctrl.Result{}, err
    }

    // ⑤ Service 조정
    if err := r.reconcileService(ctx, &app); err != nil {
        r.setCondition(&app, "Ready", metav1.ConditionFalse, "ServiceFailed", err.Error())
        _ = r.updateStatus(ctx, &app)
        return ctrl.Result{}, err
    }

    // ⑥ status 갱신
    app.Status.ReadyReplicas = deploy.Status.ReadyReplicas
    app.Status.Selector = fmt.Sprintf("app=%s,managed-by=webapp-operator", app.Name)
    app.Status.ObservedGeneration = app.Generation

    desired := ptr.Deref(app.Spec.Replicas, 1)
    switch {
    case deploy.Status.ReadyReplicas == desired && desired > 0:
        app.Status.Phase = "Running"
        r.setCondition(&app, "Ready", metav1.ConditionTrue, "AllReplicasReady",
            fmt.Sprintf("%d/%d replicas ready", deploy.Status.ReadyReplicas, desired))
    case deploy.Status.ReadyReplicas < desired:
        app.Status.Phase = "Progressing"
        r.setCondition(&app, "Ready", metav1.ConditionFalse, "ReplicasNotReady",
            fmt.Sprintf("%d/%d replicas ready", deploy.Status.ReadyReplicas, desired))
    default:
        app.Status.Phase = "Running"
        r.setCondition(&app, "Ready", metav1.ConditionTrue, "Scaled", "scaled to zero")
    }

    if err := r.updateStatus(ctx, &app); err != nil {
        return ctrl.Result{}, err
    }

    logger.V(1).Info("reconciled", "phase", app.Status.Phase,
        "ready", app.Status.ReadyReplicas, "desired", desired)
    return ctrl.Result{}, nil
}

func (r *WebAppReconciler) reconcileDeployment(
    ctx context.Context, app *demov1.WebApp) (*appsv1.Deployment, error) {

    deploy := &appsv1.Deployment{
        ObjectMeta: metav1.ObjectMeta{
            Name:      app.Name,
            Namespace: app.Namespace,
        },
    }

    // ★ CreateOrUpdate — 멱등성의 핵심
    _, err := controllerutil.CreateOrUpdate(ctx, r.Client, deploy, func() error {
        labels := map[string]string{
            "app":                          app.Name,
            "managed-by":                   "webapp-operator",
            "app.kubernetes.io/name":       app.Name,
            "app.kubernetes.io/managed-by": "webapp-operator",
        }

        deploy.Labels = labels
        deploy.Spec.Replicas = app.Spec.Replicas
        deploy.Spec.Selector = &metav1.LabelSelector{
            MatchLabels: map[string]string{
                "app":        app.Name,
                "managed-by": "webapp-operator",
            },
        }
        deploy.Spec.Template = corev1.PodTemplateSpec{
            ObjectMeta: metav1.ObjectMeta{Labels: labels},
            Spec: corev1.PodSpec{
                SecurityContext: &corev1.PodSecurityContext{      // 18.2절
                    RunAsNonRoot:   ptr.To(true),
                    SeccompProfile: &corev1.SeccompProfile{Type: corev1.SeccompProfileTypeRuntimeDefault},
                },
                Containers: []corev1.Container{{
                    Name:  "app",
                    Image: app.Spec.Image,
                    Ports: []corev1.ContainerPort{{
                        Name:          "http",
                        ContainerPort: app.Spec.Port,
                    }},
                    Env:       app.Spec.Env,
                    Resources: app.Spec.Resources,
                    SecurityContext: &corev1.SecurityContext{
                        AllowPrivilegeEscalation: ptr.To(false),
                        Capabilities:             &corev1.Capabilities{Drop: []corev1.Capability{"ALL"}},
                    },
                    ReadinessProbe: &corev1.Probe{               // 6.2절
                        ProbeHandler: corev1.ProbeHandler{
                            TCPSocket: &corev1.TCPSocketAction{
                                Port: intstr.FromString("http"),
                            },
                        },
                        InitialDelaySeconds: 2,
                        PeriodSeconds:       5,
                        TimeoutSeconds:      3,
                    },
                }},
            },
        }

        // ★ 소유 관계 설정 — GC가 자동 정리한다 (4.2절)
        return controllerutil.SetControllerReference(app, deploy, r.Scheme)
    })

    return deploy, err
}

func (r *WebAppReconciler) reconcileService(ctx context.Context, app *demov1.WebApp) error {
    svc := &corev1.Service{
        ObjectMeta: metav1.ObjectMeta{
            Name:      app.Name,
            Namespace: app.Namespace,
        },
    }

    _, err := controllerutil.CreateOrUpdate(ctx, r.Client, svc, func() error {
        svc.Labels = map[string]string{"managed-by": "webapp-operator"}
        svc.Spec.Selector = map[string]string{
            "app":        app.Name,
            "managed-by": "webapp-operator",
        }
        svc.Spec.Ports = []corev1.ServicePort{{
            Name:       "http",
            Port:       80,
            TargetPort: intstr.FromString("http"),
            Protocol:   corev1.ProtocolTCP,
        }}
        return controllerutil.SetControllerReference(app, svc, r.Scheme)
    })
    return err
}

func (r *WebAppReconciler) reconcileDelete(
    ctx context.Context, app *demov1.WebApp) (ctrl.Result, error) {

    logger := log.FromContext(ctx)

    if controllerutil.ContainsFinalizer(app, finalizerName) {
        // 외부 자원 정리 (예: 클라우드 리소스, 외부 DB 항목)
        logger.Info("cleaning up external resources")
        // ... 정리 로직 ...

        // Deployment/Service는 ownerReferences로 자동 삭제되므로 여기서 안 해도 된다

        controllerutil.RemoveFinalizer(app, finalizerName)
        if err := r.Update(ctx, app); err != nil {
            return ctrl.Result{}, err
        }
    }
    return ctrl.Result{}, nil
}

func (r *WebAppReconciler) setCondition(
    app *demov1.WebApp, condType string, status metav1.ConditionStatus, reason, msg string) {
    meta.SetStatusCondition(&app.Status.Conditions, metav1.Condition{
        Type:               condType,
        Status:             status,
        Reason:             reason,
        Message:            msg,
        ObservedGeneration: app.Generation,
    })
}

func (r *WebAppReconciler) updateStatus(ctx context.Context, app *demov1.WebApp) error {
    // ★ status 서브리소스로 쓴다 (26.3절)
    if err := r.Status().Update(ctx, app); err != nil {
        if apierrors.IsConflict(err) {
            // 충돌은 다음 조정에서 해결된다 — 에러로 취급하지 않는다
            return nil
        }
        return err
    }
    return nil
}

func (r *WebAppReconciler) SetupWithManager(mgr ctrl.Manager) error {
    return ctrl.NewControllerManagedBy(mgr).
        For(&demov1.WebApp{}).
        Owns(&appsv1.Deployment{}).      // ★ 소유한 Deployment 변경도 조정을 촉발
        Owns(&corev1.Service{}).
        Complete(r)
}
```


**효과**
- WebApp을 삭제하면 Deployment도 자동 삭제된다(가비지 컬렉션)
- `Owns()`와 함께 쓰면 Deployment 변경 시 소유자의 조정이 촉발된다

**② `controllerutil.CreateOrUpdate`**

```go
_, err := controllerutil.CreateOrUpdate(ctx, r.Client, obj, func() error {
    // obj를 원하는 상태로 만든다
    return nil
})
```

**동작**
1. `obj`를 조회한다
2. 없으면 mutate 함수를 실행하고 Create
3. 있으면 mutate 함수를 실행하고, **변경이 있을 때만** Update

**"변경이 있을 때만"이 중요하다.** 매번 Update하면 `resourceVersion`이 바뀌어 watch 이벤트가 발생하고, 그것이 다시 조정을 촉발하는 **무한 루프**가 된다.

**③ `Owns()`**

```go
ctrl.NewControllerManagedBy(mgr).
    For(&demov1.WebApp{}).           // 이 타입을 조정한다
    Owns(&appsv1.Deployment{}).      // 이 타입의 변경도 감시한다
    Complete(r)
```

Deployment가 변경되면 **그 소유자인 WebApp의 조정이 큐에 들어간다.** 누군가 Deployment의 replicas를 손으로 바꿔도 컨트롤러가 되돌린다.

**더 복잡한 매핑**

```go
ctrl.NewControllerManagedBy(mgr).
    For(&demov1.WebApp{}).
    Owns(&appsv1.Deployment{}).
    Watches(
        &corev1.ConfigMap{},
        handler.EnqueueRequestsFromMapFunc(r.findWebAppsForConfigMap),
    ).
    WithOptions(controller.Options{MaxConcurrentReconciles: 3}).
    Complete(r)
```

소유 관계가 없는 리소스(예: 참조하는 ConfigMap)의 변경에도 반응할 수 있다.

## 27.4 조정 루프 작성 원칙

### 반환값의 의미

```go
// ① 성공 — 다음 이벤트까지 대기
return ctrl.Result{}, nil

// ② 에러 — 지수 백오프로 재시도 (25.5절의 워크큐 동작)
return ctrl.Result{}, err

// ③ 특정 시간 후 재조정 (외부 상태를 폴링할 때)
return ctrl.Result{RequeueAfter: 30 * time.Second}, nil

// ④ 즉시 재조정 (백오프 적용) — 권장하지 않음
return ctrl.Result{Requeue: true}, nil
```

> **⚠️ `Requeue: true`를 남용하지 마라**
> 무한 루프의 원인이 된다. **아직 준비되지 않은 상태를 기다린다면 `RequeueAfter`를 쓴다.**
>
> 사실 대부분의 경우 아무것도 필요 없다. 관심 있는 리소스를 `Owns()`나 `Watches()`로 감시하면, 변화가 있을 때 자동으로 조정이 촉발되기 때문이다.

### 멱등성

```go
// ❌ 매번 만든다 — 두 번째 조정에서 AlreadyExists 에러
r.Create(ctx, deployment)

// ❌ 매번 업데이트한다 — resourceVersion이 계속 바뀌어 무한 루프
r.Update(ctx, deployment)

// ✅ 필요할 때만 변경한다
controllerutil.CreateOrUpdate(ctx, r.Client, deploy, func() error { ... })
```

**무한 루프 진단**

```bash
kubectl logs -n <ns> <controller-pod> | grep -c "reconciling"
# 1분에 수천 번 나오면 무한 루프
```

원인은 대개 **조정이 자기 자신을 변경**하는 것이다.

```go
// ❌ 매 조정마다 애노테이션에 타임스탬프를 쓴다
app.Annotations["last-reconciled"] = time.Now().String()
r.Update(ctx, app)      // → 변경 이벤트 → 조정 → 무한 루프
```

### 에러 처리

```go
// ① 재시도해도 소용없는 에러 — 로그만 남기고 성공 반환
if apierrors.IsInvalid(err) {
    logger.Error(err, "invalid spec, not retrying")
    r.Recorder.Event(&app, corev1.EventTypeWarning, "InvalidSpec", err.Error())
    r.setCondition(&app, "Ready", metav1.ConditionFalse, "InvalidSpec", err.Error())
    _ = r.updateStatus(ctx, &app)
    return ctrl.Result{}, nil        // ★ nil을 반환해 재시도하지 않는다
}

// ② 일시적 에러 — 재시도
if apierrors.IsConflict(err) || apierrors.IsServerTimeout(err) {
    return ctrl.Result{}, err        // 백오프 재시도
}

// ③ 외부 시스템 대기 — 지연 재조정
if !externalResourceReady {
    return ctrl.Result{RequeueAfter: 10 * time.Second}, nil
}
```

**에러를 그대로 반환하면 무한 재시도된다.** 사용자의 잘못된 설정 때문이라면 status에 기록하고 멈춰야 한다.

### 파이널라이저 사용 지침

```go
if !app.DeletionTimestamp.IsZero() {
    // 삭제 중
    if controllerutil.ContainsFinalizer(app, finalizerName) {
        if err := r.cleanupExternal(ctx, app); err != nil {
            return ctrl.Result{}, err       // 정리 실패 시 재시도
        }
        controllerutil.RemoveFinalizer(app, finalizerName)
        return ctrl.Result{}, r.Update(ctx, app)
    }
    return ctrl.Result{}, nil
}
```

> **⚠️ 파이널라이저는 정말 필요할 때만**
> 4.2절에서 본 것처럼, 컨트롤러가 죽으면 파이널라이저를 제거해 줄 주체가 없어 리소스가 영원히 `Terminating`에 남는다.
>
> **`ownerReferences`로 처리되는 정리에는 파이널라이저가 필요 없다.** 클러스터 밖의 자원(클라우드 리소스, 외부 DB 항목)을 정리할 때만 쓴다.
>
> 그리고 **정리 로직은 멱등해야 한다.** 이미 삭제된 것을 다시 삭제하려 해도 성공해야 한다.

## 27.5 Operator SDK와 다른 접근법

### Operator SDK

Kubebuilder를 기반으로 하되 OLM(Operator Lifecycle Manager) 통합과 세 가지 타입을 제공한다.

```bash
operator-sdk init --domain example.com --plugins go/v4
operator-sdk create api --group demo --version v1 --kind WebApp --resource --controller
```

| 타입 | 설명 |
|---|---|
| **Go** | Kubebuilder와 사실상 동일 |
| **Ansible** | Ansible 플레이북으로 조정 로직 작성 |
| **Helm** | Helm 차트를 CR로 감싼다 |

**Helm 오퍼레이터**가 흥미롭다.

```bash
operator-sdk init --plugins helm --domain example.com
operator-sdk create api --group demo --version v1 --kind WebApp --helm-chart=./charts/webapp
```

**CR의 spec이 Helm values가 되고, 조정이 `helm upgrade`가 된다.** Go 코드를 한 줄도 쓰지 않고 Level 1~2 오퍼레이터를 만들 수 있다(24.3절).

**한계**: Helm이 표현할 수 없는 로직(페일오버, 백업)은 불가능하다. Level 3 이상이 필요하면 Go로 가야 한다.

### Metacontroller

**어떤 언어로든** 웹훅 서버만 만들면 컨트롤러가 된다.

```yaml
apiVersion: metacontroller.k8s.io/v1alpha1
kind: CompositeController
metadata:
  name: webapp-controller
spec:
  parentResource:
    apiVersion: demo.example.com/v1
    resource: webapps
  childResources:
    - apiVersion: apps/v1
      resource: deployments
    - apiVersion: v1
      resource: services
  hooks:
    sync:
      webhook:
        url: http://webapp-hook.default/sync
```

**웹훅이 받는 것과 반환하는 것**

```python
# 어떤 언어로든 가능
def sync(request):
    parent = request["parent"]           # WebApp
    children = request["children"]       # 현재 자식들

    return {
        "status": {"phase": "Running"},
        "children": [                    # ★ 원하는 자식들을 선언
            {"apiVersion": "apps/v1", "kind": "Deployment", ...},
            {"apiVersion": "v1", "kind": "Service", ...},
        ]
    }
```

**Metacontroller가 diff와 적용을 대신한다.** 개발자는 "원하는 자식 목록"만 반환하면 된다.

### Kopf (Python)

```python
import kopf
import kubernetes.client as k8s

@kopf.on.create('demo.example.com', 'v1', 'webapps')
@kopf.on.update('demo.example.com', 'v1', 'webapps')
def reconcile(spec, name, namespace, patch, logger, **kwargs):
    replicas = spec.get('replicas', 1)
    image = spec['image']

    deploy = build_deployment(name, namespace, image, replicas)
    kopf.adopt(deploy)                   # ownerReferences 설정

    api = k8s.AppsV1Api()
    try:
        api.create_namespaced_deployment(namespace, deploy)
    except k8s.ApiException as e:
        if e.status == 409:
            api.patch_namespaced_deployment(name, namespace, deploy)
        else:
            raise

    patch.status['phase'] = 'Running'
    logger.info(f"reconciled {name}")
```

**Python 팀에게는 매우 실용적이다.** 데코레이터 기반이라 학습 곡선이 낮다.

### Crossplane Compositions

**코드 없이 YAML만으로** 여러 리소스를 조합한다.

```yaml
apiVersion: apiextensions.crossplane.io/v1
kind: Composition
spec:
  compositeTypeRef:
    apiVersion: demo.example.com/v1
    kind: XWebApp
  mode: Pipeline
  pipeline:
    - step: patch-and-transform
      functionRef: { name: function-patch-and-transform }
      input:
        resources:
          - name: deployment
            base:
              apiVersion: kubernetes.crossplane.io/v1alpha2
              kind: Object
              spec:
                forProvider:
                  manifest:
                    apiVersion: apps/v1
                    kind: Deployment
                    ...
            patches:
              - fromFieldPath: spec.replicas
                toFieldPath: spec.forProvider.manifest.spec.replicas
```

**클라우드 리소스까지 함께 프로비저닝**할 수 있다는 것이 강점이다. "이 앱을 배포하면서 RDS 인스턴스와 S3 버킷도 함께" 같은 요구에 적합하다.

### 선택 가이드

| 상황 | 권장 |
|---|---|
| Go 역량 있음, 복잡한 로직 | **Kubebuilder** |
| Helm 차트가 이미 있음, Level 1~2 | **Operator SDK (Helm)** |
| Python/Java 팀 | **Kopf / Java Operator SDK** |
| 언어 자유, 단순한 조합 | **Metacontroller** |
| 클라우드 리소스까지 함께 | **Crossplane** |
| Red Hat 생태계, OLM 배포 | **Operator SDK** |

## 실습 과제

**과제 1 — Ingress 추가**
WebApp에 `spec.host` 필드를 추가하고, 값이 있으면 Ingress를 생성하도록 조정 함수를 확장한다. `spec.host`가 제거되면 Ingress도 삭제되어야 한다(멱등성 주의).

**과제 2 — 무한 루프 재현**
조정 함수에 `app.Annotations["reconciled-at"] = time.Now().String()`과 `r.Update(ctx, &app)`를 넣고 무한 루프를 재현한다. `controller_runtime_reconcile_total` 메트릭이 폭증하는 것을 확인한 뒤 원인을 설명한다.

**과제 3 — 파이널라이저 정리 로직**
삭제 시 외부 파일에 로그를 남기는 정리 로직을 구현한다. 정리가 실패하도록 만들어 리소스가 `Terminating`에 머무는 것을 확인하고, 컨트롤러를 정지시킨 뒤 파이널라이저를 수동 제거해 본다.

**과제 4 — ConfigMap 변경 감시**
`spec.configMapRef`를 추가하고, 참조된 ConfigMap이 바뀌면 Deployment를 롤아웃하도록 `Watches()`와 매핑 함수를 구현한다. 7.6절의 체크섬 패턴을 컨트롤러가 자동으로 수행하는 셈이다.

**과제 5 — envtest 통합 테스트**
다음 시나리오를 테스트로 작성한다.
- WebApp 생성 → Deployment와 Service가 생성된다
- replicas 변경 → Deployment의 replicas가 따라간다
- Deployment 수동 수정 → 원래대로 복구된다
- WebApp 삭제 → 자식들이 삭제된다

## 요약

- **마커 주석이 코드 생성의 입력**이다. Go 타입 하나에서 DeepCopy, CRD 매니페스트, RBAC이 모두 생성되므로 **Go 타입이 진실의 원천**이 된다.
- **sample-controller는 참조용**이고, 새 프로젝트는 controller-runtime을 쓴다. 다만 `metav1.IsControlledBy`로 **남의 리소스를 건드리지 않는 확인**은 어느 방식에서든 필수다.
- 핵심 API 셋: **`SetControllerReference`**(소유 관계 → 자동 GC), **`CreateOrUpdate`**(멱등적 조정), **`Owns()`**(자식 변경 시 부모 조정 촉발).
- **`CreateOrUpdate`가 "변경이 있을 때만" 업데이트하는 것이 중요하다.** 매번 Update하면 watch 이벤트가 발생해 무한 루프가 된다.
- 반환값: 성공은 `{}, nil`, 재시도는 `{}, err`, 지연 재조정은 `{RequeueAfter: ...}, nil`. **사용자의 잘못된 설정으로 인한 에러는 status에 기록하고 `nil`을 반환**해 무한 재시도를 막는다.
- 관측성 세 축: **이벤트**(`Recorder`, `kubectl describe`에 표시), **구조화된 로깅**, **메트릭**(controller-runtime이 기본 제공).
- **파이널라이저는 클러스터 밖의 자원을 정리할 때만** 쓴다. `ownerReferences`로 처리되는 것에는 불필요하며, 컨트롤러가 죽으면 리소스가 영원히 `Terminating`에 남는다.
- **envtest**는 실제 API 서버를 띄워 통합 테스트를 가능하게 한다. kubelet이 없어 Pod는 뜨지 않지만 API 수준 동작은 완전히 검증된다.
- Go가 아니어도 된다. **Helm 오퍼레이터**(코드 없이 Level 1~2), **Metacontroller**(언어 자유), **Kopf**(Python), **Crossplane**(클라우드 리소스까지) 등 상황에 맞는 선택지가 있다.

**다음 장에서는** 6부의 마지막으로 어드미션 웹훅과 커스텀 API 서버를 다룬다. 정책을 API 경로에 주입하고, 완성한 오퍼레이터를 프로덕션에 출하하는 방법까지 살펴본다.
